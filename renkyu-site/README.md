# 連休カレンダー

日本の祝日と連休を計算し、静的サイトとして生成する。

外部 API やスクレイピングに依存しない。祝日は「国民の祝日に関する法律」を
そのまま実装しているので、データ提供元が消えてもサイトは動き続ける。

## 使い方

```bash
cd renkyu-site
python test_holidays.py          # 祝日計算の検証 (実際の官報値と照合)
python build.py                  # dist/ に静的サイトを生成
python build.py --years 10       # 10年先まで生成
python build.py --today 2027-01-01   # 基準日を変えて表示確認

python -m http.server 8000 -d dist   # ローカルで確認
```

Python 3.11 以降。サードパーティ製ライブラリは不要。

## ファイル

| ファイル | 役割 |
|---|---|
| `holidays.py` | 祝日の計算エンジン。法律とその改正をそのまま実装 |
| `renkyu.py` | 連続した休日 (連休) の検出と、GW / SW / 年末年始の判定 |
| `holiday_info.py` | 祝日ごとの趣旨・制定経緯の解説文 |
| `theme.py` | HTML テンプレート |
| `build.py` | サイト生成のエントリポイント |
| `test_holidays.py` | 回帰テスト |
| `static/style.css` | スタイルシート |

## 生成されるページ

| URL | 内容 |
|---|---|
| `/` | 次の連休までのカウントダウン、直近2年の連休 |
| `/y/YYYY/` | その年の祝日一覧と連休一覧 |
| `/renkyu/YYYY-MM-DD/` | 個別の連休の詳細 (日並び、含まれる祝日) |
| `/holiday/` | 祝日の一覧と法律上の趣旨 |
| `/holiday/<slug>/` | 個別の祝日の意味・由来・各年の日付 |
| `/about/` | 計算方法と正確性の注意 |
| `/sitemap.xml` | サイトマップ |
| `/holidays.json` | 祝日データ (再利用可能な JSON) |

デフォルトで約 90 ページ。`--years` を増やせばページ数も増える。

## 実装している祝日の制度

- 日付が固定の祝日 (元日、憲法記念日など)
- ハッピーマンデー制度 (成人の日、海の日、敬老の日、スポーツの日)
- 春分の日・秋分の日の天文計算
- 振替休日 (2007年改正後の「翌日以降の最も近い平日」ルール)
- 国民の休日 (祝日に挟まれた平日)
- 天皇誕生日の代替わりによる移動 (4/29 → 12/23 → 2/23)
- 4/29 の名称変遷 (天皇誕生日 → みどりの日 → 昭和の日)
- 特例: 2019年の即位関連休日、2020・2021年のオリンピックに伴う祝日移動

`test_holidays.py` で 2015・2019・2020・2021・2024・2025・2026 年の
実際の祝日と全件照合している。

## 既知の制約

- **春分の日・秋分の日は予測値を含む。** 正式には前年2月1日の官報で告示される。
  近似式は 1900〜2099 年を対象としており、それ以降は計算しない。
- **将来の法改正は反映されない。** 新しい祝日が追加された場合は
  `holidays.py` の更新が必要。
- 年末年始やお盆は法律上の祝日ではないため、連休判定には
  1月1日と土日以外は含まれない。

## 公開

`.github/workflows/renkyu-site.yml` が毎日 00:10 JST にビルドし、
GitHub Pages へデプロイする。「次の連休まであと何日」の表示はこれで自動更新される。
手動で即座に反映したいときは Actions タブから workflow_dispatch で実行する。

初回のみリポジトリ側の設定が必要:

1. リポジトリの **Settings → Pages → Build and deployment** で
   Source を **GitHub Actions** に変更する
2. `theme.py` の `BASE_URL` を実際の公開 URL に書き換える
   (canonical URL と sitemap に使われる)
3. push のたびに自動デプロイしたい場合は、ワークフローの `push:` の
   コメントを外し、`branches:` にデフォルトブランチ名を書く。
   ブランチを限定しないと作業ブランチへの push で本番が上書きされる

## 収益化について

`theme.py` の `affiliate_block()` が広告の差し込み位置になっている。
現在はプレースホルダで、実際のリンクは入っていない。

ASP の審査は「中身のあるサイト」であることが前提なので、
ページが揃ってから申し込むこと。掲載時は `PR` 表記を維持する
(景品表示法のステルスマーケティング規制への対応)。
