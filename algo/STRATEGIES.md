# 戦略台帳

見つけた戦略をここに 1 本ずつ凍結して保管する。
各戦略は `algo/strategies/sNNN_*.py` に単体で実行できる形で置き、
このファイルには「何を・なぜ・どこまで確認したか」を残す。

共通基盤は `algo/engine.py` (データ読み込み / タイムゾーン / pip / スプレッド)。
スプレッド前提を変えるときは `engine.SPREAD_PIP` を書き換えれば全戦略に伝播する。

## S002 東京朝の円売りドリフト 【凍結】

`algo/strategies/s002_tokyo_am.py`

**営業日ごとに**、4 円クロスを **06:00 → 08:45 JST** でロング。
ゴトー日限定をやめた版で、取引回数が S001 の約 4 倍。

| 項目 | 値 |
|---|---|

| 平均 | +2.35pip / t = +6.78 |

### 発見の経緯

`algo/screen_hourly.py` で「JST の h 時に入って k 時間持つ」を 2304 通り総当たりし、
train (2012-2018) で Bonferroni (|t|>3.9) を突破し、かつ test (2019-2022) でも
同方向だったのは **GBPJPY 6時ロング** の 1 件のみ。
これを 4 ペアに広げ、15 分刻みで入口/出口を詰めたのが S002。

### 頑健性チェック (スプレッド 0.2pip 前提)

| 条件 | n | 平均 | t | 勝率 |
|---|---|---|---|---|
| 全体 | 2185 | +2.35 | +6.78 | 61.0% |
| 2021 除外 | 1946 | +2.03 | +5.27 | 58.5% |
| 2020-2021 除外 | 1709 | +1.78 | +4.26 | 57.5% |
| 月曜 除外 | 1912 | +1.55 | +4.31 | 59.2% |
| **ゴトー日 除外** | 1757 | +2.07 | **+5.16** | 60.4% |
| ゴトー日+2021 除外 | 1564 | +1.76 | +3.97 | 58.2% |
| **ゴトー日+2021+月曜 除外** | 1371 | +1.08 | **+2.32** | 56.4% |

- **ゴトー日を除いても t=+5.16** → S001 の焼き直しではなく独立した現象。
- 三重に削っても t=+2.32 で生存。
- **年別で 10 年すべてプラス** (最弱 2019 +0.33pip、最強 2021 +5.02pip)。
- **4 ペアすべて単独でプラス** (USDJPY t=+4.15 / EURJPY +7.00 / GBPJPY +7.49 / AUDJPY +4.59)。

### スプレッド感応度 ← 最大の弱点

| 想定スプレッド | 平均 | t | 勝率 |
|---|---|---|---|
| 0.2pip | +2.35 | +6.78 | 61.0% |
| 0.5pip | +2.05 | +5.91 | 59.3% |
| 1.0pip | +1.55 | +4.47 | 57.5% |
| **2.0pip** | **+0.55** | **+1.59** | 52.4% |

**2pip でほぼ消える。** 東京朝は流動性がある時間帯なので 03:00 (S001) より条件は良いが、
GBPJPY / AUDJPY は 1pip 超が普通。**ペアごとの実スプレッド測定が必須。**

### 既知のリスク

- **2021 年 5〜10 月が異常。** 2021-08 は 22 営業日中 **22 勝**。勝率61%の戦略で
  22 連勝は確率 0.0006%。除外しても t=+5.27 で戦略は生存するが、この 6 ヶ月分
  (約29万円 = 累計の14%) は割り引いて見ること。原因未特定。
- **ENTRY=06:00 は月曜が週明けオープン直後**にあたり、データ欠損が 9% ある。
  アーティファクトを避けるなら `ENTRY="07:00"` (欠損ゼロ、n=2400) を使う。
  ただし成績は落ちる (+1.73pip / t=+5.38)。

### テールリスク ← レバレッジを決める前に必ず読む

保有 1h45m の建玉リターン分布:

| 指標 | 値 |
|---|---|
| SD | 0.1365% |
| 下位 5% 点 | -0.164% |
| 下位 1% 点 | -0.361% |
| 下位 0.1% 点 | -0.721% |
| **過去最悪** | **-2.045%** |

最悪の 5 日:

| 日付 | 損失 | 事象 |
|---|---|---|
| 2016-06-24 | -2.045% | Brexit 投票結果 |
| **2019-01-03** | **-1.669%** | **アップルショックのフラッシュクラッシュ** |

2019-01-03 は **本戦略の保有時間帯そのもの** で起きた。
早朝東京は 1 日で最も板が薄く、それがエッジの源泉であると同時にテールの源泉。
**エッジとテールが同じ原因から来ている** ことを忘れないこと。

### 調整の仕方

```python
from algo.strategies import s002_tokyo_am as s
# 入口/出口の総当たり (train/test の t も同時に出る)
s.sweep(entries=["05:00","05:30","06:00","06:30","07:00","07:30"],
        exits=["08:00","08:15","08:30","08:45","09:00","09:30","09:45"])
```

調整するときの原則:
1. **train/test 両方の t を見る。** train だけ良いものは採らない。
2. **ゴトー日除外でも残るか**を毎回確認する。残らなければ S001 の重複でしかない。
3. **スプレッド 1.0pip でも生き残るか**を確認する。生き残らなければ実運用に出せない。
4. 曜日・年・ペアで**削っても符号が変わらないか**を確認する。

## ショート方向の探索結果 (2026-08-26) — **採用に足るものは見つからなかった**

`algo/screen_short.py` で 1008 通り (6ペア x 24時刻 x 7保有) をショート方向で検定。
2012-2022 は構造的な円安期なので、素の結果と **ドリフト除去後** の両方を出した。

### 棄却した仮説 (再探索しないこと)

| 仮説 | 結果 | 判定 |
|---|---|---|
| EURUSD/GBPUSD ロンドン時間 (JST 13-19時) ショート | train t=+3.4 だが **test t=+1.0 前後に劣化** | 棄却 |
| 円クロス 仲値後の押し戻し (09:45 → 欧米時間 ショート) | 最良でも t=+1.96 | 棄却 |
| 前日大きく上げた翌朝は下げる (リバーサル) | **逆だった。前日上げた翌朝ほど S002 が強い** | 棄却 |
| 円クロスの時間帯ショート全般 | ドリフト除去後も有意なものなし | 棄却 |

### 唯一の候補 (保留)

**GBPUSD 05:00 → 07:00 JST ショート**

| 項目 | 値 |
|---|---|
| 全体 | n=1915 +1.16pip t=+3.95 勝率55.2% |
| train / test | t=+2.74 / **t=+3.06** (劣化していない) |
| **S002 との相関** | **-0.037 (ほぼ独立)** |

分散効果は魅力的だが、**採用しない**。理由:

1. **スプレッドで消える。** 0.5pip で t=+2.93、**1.0pip で t=+1.24**、2.0pip で負。
   05:00 JST は NY クローズ後で世界的に最も板が薄い時間帯。GBPUSD の実スプレッドは
   この時間 1.5〜3pip が普通。**構造的に取れない。**
2. **年別が不安定。** 2013 +0.02 / 2014 +0.15 / 2016 +0.20 / 2020 +0.54 と
   10 年のうち 4 年がほぼゼロ。

### なぜショートが見つからないのか (構造的な理由)

ロング側 (S001/S002) のエッジは **「価格を気にせず買わざるを得ない主体がいる」**
ことに由来する — 輸入企業は仲値までに必ずドルを買う。値段は二の次。

ショート側に同じ構造が無い。**「決まった時刻に必ず円を買わなければならない主体」**が
存在しない。輸出企業の円買いは仲値に集中せず、期日も分散している。

`EDGE_IDEAS.md` の設計条件「なぜ動くのかを一文で説明できる」を満たすショートが
無い以上、統計だけで拾ったショートは high risk。**ショートは当面探さない。**
